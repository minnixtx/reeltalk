{% comment %} One reply row (feed interactions increment 4). A partial rather than inline markup because two callers render it: the post page's thread loop, and ``reply_to_status``, which hands this same render back as a JSON string for comments.js to insert. One template means the row the client appends cannot drift from the row the page renders — the client inserts what the server rendered instead of rebuilding it. ``reply`` is the reply Status; ``reply_to`` is who it answers, already resolved to display text by the view: "" for a direct reply to the post, "a hidden reply" or "a deleted reply" when naming the author would name something this viewer is not shown. The caller also stamps ``reply.deletable``, the same flag both of its callers can set — see the delete control below. The row wears ``reply-row``, **not** ``reply``. ``.reply`` is the reply *control's* class (``reeltalk.css`` — ``display: inline-flex``), and the row used to carry it too, which made every reply on every post page lay its head and its body side by side instead of one under the other. Measured on the live instance before the fix: head right edge 531, body left edge 537, on ``/status/1/``, ``/status/56/`` and ``/list/4/`` alike. Keeping the two names apart also stops ``comments.js``'s ``querySelector(".reply")`` from being able to reach a thread row at all — today it reaches the control only by document order, not by construction. {% endcomment %}
